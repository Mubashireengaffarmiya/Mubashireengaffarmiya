# Profile README setup

This workspace contains the profile README and its supporting assets and automation. The special GitHub profile repository must be named exactly after the account: `Mubashireengaffarmiya`.

## What is in this project

```text
README.md
SETUP.md
assets/
  holographic-banner.svg
  ai-animation.svg
  developer-graphics.svg
.github/
  workflows/
    3d-contributions.yml
    snake-animation.yml
```

The hero banner and AI illustration are local SVGs. The contribution calendar and snake are generated by GitHub Actions. Their images will appear after the first successful workflow runs.

## Enable GitHub Actions

1. Create or open the public repository `Mubashireengaffarmiya/Mubashireengaffarmiya`.
2. Upload this project's files to the repository's default branch. The workflows use the automatically provided `GITHUB_TOKEN`; no API key or manually created secret is needed for public contribution data.
3. In the repository, open **Settings → Actions → General**. Under **Workflow permissions**, select **Read and write permissions**, then save. The workflows also declare `contents: write` explicitly.
4. Open **Actions** and enable workflows if GitHub prompts you.
5. Run **3D Contribution Calendar** and **Contribution Snake Animation** once with **Run workflow**. The first workflow commits `profile-3d-contrib/profile-night-rainbow.svg` to the default branch. The second publishes `github-contribution-grid-snake.svg` and `github-contribution-grid-snake-dark.svg` to the `output` branch.
6. If repository rules or branch protection prevent workflow pushes, allow GitHub Actions to write to the required branch or adjust the rules. No workflow can bypass repository protections.

Both workflows are also scheduled daily. GitHub scheduled runs use UTC and can be delayed during periods of high load. To include private contribution counts, enable **Include private contributions** in your GitHub profile settings; the default token intentionally uses public profile data.

## Actions and generated paths

- `3d-contributions.yml` uses `actions/checkout` and `yoshi389111/github-profile-3d-contrib` to generate `profile-3d-contrib/profile-night-rainbow.svg`. It stages only that generated directory and skips the commit/push when there are no changes.
- `snake-animation.yml` uses `Platane/snk` to create the light and dark SVGs in `dist/`, then publishes that directory to the `output` branch with `crazy-max/ghaction-github-pages`. It sets `allow_empty_commit: false` so unchanged output does not create empty commits.
- The README points to the exact paths produced by these workflows. The snake images will be unavailable until the first snake workflow run creates the `output` branch.

## Validate locally

From PowerShell in this folder:

```powershell
# Parse all custom SVG files as XML
[xml](Get-Content -Raw .\assets\holographic-banner.svg) | Out-Null
[xml](Get-Content -Raw .\assets\ai-animation.svg) | Out-Null
[xml](Get-Content -Raw .\assets\developer-graphics.svg) | Out-Null

# Confirm each required workflow and asset exists
Test-Path .\README.md
Test-Path .\SETUP.md
Test-Path .\.github\workflows\3d-contributions.yml
Test-Path .\.github\workflows\snake-animation.yml
```

GitHub is the authoritative renderer for profile README HTML and remote SVGs. Review the rendered profile after uploading, then run each workflow from **Actions** to populate the contribution visuals.

## Upload with PowerShell

These commands do not push automatically. Run them yourself from PowerShell after reviewing the files. If you already created the GitHub repository, clone it and copy these project files into the clone (keeping the `.github` and `assets` directories):

```powershell
git clone https://github.com/Mubashireengaffarmiya/Mubashireengaffarmiya.git
Copy-Item .\README.md .\Mubashireengaffarmiya\
Copy-Item .\SETUP.md .\Mubashireengaffarmiya\
Copy-Item .\assets .\Mubashireengaffarmiya\ -Recurse
Copy-Item .\.github .\Mubashireengaffarmiya\ -Recurse
Set-Location .\Mubashireengaffarmiya
git status --short
git add README.md SETUP.md assets .github
git commit -m "Build holographic GitHub profile"
git push origin HEAD
```

If you are already in the cloned profile repository, skip `git clone` and the copy commands; review `git status`, then stage, commit, and push the intended files.
